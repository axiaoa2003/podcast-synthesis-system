# 优化文稿读取功能

## 问题分析
根据用户反馈，后端未能正确读取包含结构化内容`(情绪,语速,语调)`的文稿请求。当前系统已经支持逐句情绪参数，但可能存在参数传递或解析问题。

## 改进计划

### 1. 增强文稿解析功能
- **文件**: `podcast_utils.py`
- **函数**: `parse_dialogue`
- **改进**: 
  - 增强正则表达式，确保`[角色](情绪,语速,语调): 内容`格式被正确匹配
  - 添加更详细的解析日志
  - 增强错误处理，提供更明确的解析错误信息

### 2. 优化音频合成路由
- **文件**: `app.py`
- **路由**: `api_synthesize_audio`
- **改进**: 
  - 确保情绪、语速、语调参数被正确接收
  - 添加更详细的日志记录，便于调试
  - 增强错误处理，提供更明确的错误信息
  - 添加参数验证，确保参数在有效范围内

### 3. 改进音频生成逻辑
- **文件**: `podcast_utils.py`
- **函数**: `generate_audio_segments`
- **改进**: 
  - 确保逐句参数被正确使用
  - 添加更详细的日志记录
  - 增强错误处理，提供更明确的错误信息

### 4. 增强MiniMax客户端
- **文件**: `minimax_client.py`
- **函数**: `synthesize_speech`
- **改进**: 
  - 确保所有参数被正确传递到API
  - 添加更详细的请求日志
  - 增强错误处理，提供更明确的API错误信息

### 5. 增强文稿验证功能
- **文件**: `podcast_utils.py`
- **函数**: `validate_script`
- **改进**: 
  - 增强对结构化格式的验证
  - 添加更详细的验证日志
  - 提供更明确的验证错误信息

### 6. 添加API文档
- **文件**: `app.py`
- **改进**: 
  - 添加API文档注释
  - 提供更明确的参数说明
  - 添加示例请求和响应

## 预期效果
- 后端能够正确读取包含结构化格式的文稿请求
- 逐句情绪、语速、语调参数被正确传递和使用
- 提供更详细的日志记录，便于调试
- 提供更明确的错误信息，便于用户理解和修复问题
- 增强系统的健壮性和可靠性

## 风险评估
- **风险**: 正则表达式修改可能导致现有文稿格式不兼容
- **缓解措施**: 保留对现有格式的支持，添加向后兼容逻辑

- **风险**: 参数传递错误可能导致音频合成失败
- **缓解措施**: 添加详细的日志记录和错误处理，提供明确的错误信息

- **风险**: API调用失败可能导致系统崩溃
- **缓解措施**: 增强错误处理和重试机制，确保系统稳定性
